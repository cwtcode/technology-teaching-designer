# Anticipated difficulties and quality checks

## Select task-specific hypotheses

Use the most relevant three to six rather than a boilerplate list. If student data is provided, distinguish observed patterns from predictions.

| Possible situation | Observable signal | Prevention or response |
|---|---|---|
| Missing prerequisite or vocabulary | Cannot explain a key term or diagnostic example | Brief recap, annotated example, vocabulary support; recheck |
| Copying without understanding | Reproduces demo but cannot predict a change | Pause-and-predict, self-explanation, small independent variation |
| Losing place in procedures | Repeatedly asks for the next step | Numbered checkpoints, expected outputs, restore points, fewer simultaneous steps |
| Difficulty with variables/conditions/loops | Treats assignment as equality; wrong branch; non-terminating loop | Trace values, contrast examples, test boundary cases, connect representations |
| Difficulty debugging | Changes many things without a hypothesis | Reproduce error, isolate one cause, make one change, retest |
| Weak transfer | Cannot adapt changed input or requirement | Bridge from a small variation; fade prompts gradually |
| AI dependence | Cannot explain generated work or accepts false output | Initial human plan, small changes, explanation, independent tests |
| Agent overreach | Unreviewed changes or actions beyond the task | Bound tools/actions, review plan/diff, use sandbox, require intervention checkpoints |
| Unequal group participation | One student controls device and explains everything | Rotate roles, require individual checks, structure peer dialogue |
| Vague peer feedback | Praise focuses only on appearance | Criteria, evidence-based prompts, revision requirement |
| Different working speeds | Some wait while others cannot reach core checkpoint | Clearly bounded core, optional hints, meaningful extension |
| Language/accessibility barrier | Misreads instructions; cannot access interface or media | Plain language, captions, keyboard routes, adaptable formats; consult stated needs |
| Technical failure | Login, network, device, file or account problem | Preflight, shared/synthetic data, local copies, offline tracing or paper task |

For each selected difficulty add a check of whether the response helped. Do not infer disability or label a learner as weak from a single error.

## Quality gate

- Lesson plans follow lesson-plan-format.md unless the current teacher request specifies another layout: information table first, then Time | Content | Activity | Remarks. Preserve unknown metadata as blanks/placeholders rather than copying the reference lesson’s values.
- Objectives, activities, and assessment require the same intended learning.
- Every lesson names a suitable platform, explains its fit, and states setup, access, saving/submission, and fallback requirements.
- Every lesson has at least one realistically completable core task or project milestone with a minimum output, objective mapping, success criteria, collection method, and assessment before the lesson ends.
- Every stated objective has feasible evidence; group/AI work includes an individual check. Distinguish finishing a task from demonstrating understanding.
- Core work and its assessment fit the available time after setup, instruction, testing, feedback, revision, and saving. Reduce scope if they do not; keep extensions optional.
- Inquiry gives genuine decisions with suitable support; individual evidence is included.
- Timing includes transitions, troubleshooting, feedback, revision, and saving.
- Prerequisites and next-stage readiness are explicit; conceptual gaps are addressed.
- Theories explain decisions without proving outcomes; predictions and observations are separated.
- Curriculum references have correct jurisdiction, version/status and verified identifiers.
- Every lesson about AI has a sourced mapping to both OECD/EU AI literacy and UNESCO student competencies, with appropriate levels, task IDs, criteria and individual evidence. Keep frameworks/editions/levels distinct; label unverified mappings and teacher-designed crosswalks.
- AI-generated products are not proof of learner understanding or AI-system-design competence; assess human decisions, technical understanding and verification where relevant.
- Information/media literacy uses a clear embedded or standalone mode, age-appropriate targets, and a completed evidence-based task; do not substitute generic warnings or force AI/coding into it.
- Source packs distinguish authentic sources from fictional cases, consider context and source independence, and permit justified uncertainty; do not infer misinformation from disagreement or infer intent without evidence.
- Current trends and tool instructions are checked or honestly labelled unverified.
- Code and expected outputs agree; include normal/boundary/invalid cases when relevant. Execute when available; label unexecuted examples.
- Subject facts, units, formulas, data, and answers are correct; use synthetic data for sensitive contexts.
- Worksheet, plan, notes, and slides use consistent examples and criteria.
- Student resources omit teacher answers; open tasks have criteria and sample reasoning.
- Rendered artifacts are readable, editable where requested, and free of clipping/overlap.
- Account, device, language, accessibility and technical fallback needs are practical.
- Do not publish student information, private school documents, or user attachments as public examples.

For a curriculum map additionally verify hour totals, prerequisite order, purposeful revisiting, assessment workload, feasible teacher preparation, and a pilot/review point. Report outstanding limits rather than claiming complete alignment or effectiveness without evidence.
