# Worksheets, answers, and presentations

## Shared alignment

Use the same objectives, examples, data, vocabulary, activity IDs, test criteria, and outputs as the lesson plan. Ensure slide prompts identify the matching worksheet activity. Include enough context for a standalone resource if no plan exists. Update all dependent resources after a change. Explicitly name the lesson platform and core task in each standalone resource. Keep the task ID, minimum output, success criteria, time allowance, and submission instructions aligned across the plan, worksheet, slides, and teacher guide. Distinguish student-facing content from teacher guidance.

Use available document, presentation, spreadsheet, or PDF creation skills for actual file authoring. Do not assume those skills or proprietary tools exist in every installation. If unavailable, offer honest structured source content and describe the file limitation. Honour user templates and language choices. Keep technical implementation details out of student-facing material unless they are part of the intended learning.

Provide task-completion and learning-evidence fields appropriate to the output: expected/actual tests, an explanation or adaptation, feedback, and a recorded revision. Reserve slide time and teacher notes for checking the core task before the lesson ends. Do not substitute an optional extension for the required assessed task.

## Lesson plan document format

Follow lesson-plan-format.md for the default two-table school layout. Use its A4 portrait page setup, Times New Roman body text, grey label/header cells and four-column outline. Keep platform, task requirements and assessment evidence visible within the format. A new teacher-provided template overrides this default; do not apply the lesson-plan table format to student worksheets or slides automatically.

## Student worksheet

Include a concise purpose, success criteria, prerequisites/setup when necessary, key vocabulary, prediction or diagnostic question, worked example, numbered core tasks, expected checkpoints, a supported route, an independent variation, testing record, peer feedback/revision, and an exit reflection as appropriate to length.

Provide enough space for answers and reasoning, with clear visual separation between tasks. Keep questions and essential diagrams together. Use editable text and code; avoid screenshots of text when editable content is feasible. Reserve screenshots for genuinely visual interface explanations and provide captions. Use concise one-action instructions for novice procedures.

Set code and pseudocode in a monospaced font such as Courier New; preserve indentation. Use editable stacked fractions/equations for mathematical notation, italic mathematical variables, and a full minus sign in prose mathematics; retain valid ASCII operators and identifier styling inside executable code. Do not convert Python '-' into a typographic mathematical symbol.

Supply separate teacher answers with worked reasoning, expected outputs, alternative valid responses, likely misconceptions, testing examples, and open-task criteria. Do not place answers in student margins or disclose them through headers or notes. Do not add name/class fields if the teacher's example or preference omits them.

## PowerPoint

Create a coherent editable deck with student-facing slides and teacher-facing speaker notes. Include a launch problem, goals/criteria, essential concepts, prediction prompts, worked demo, practice checkpoints, an independent application, evaluation/revision, and conclusion as needed. Avoid a prescribed slide count; match time and complexity.

Keep one main purpose per slide and use readable code, diagrams, contrast, whitespace, and clear hierarchy. Split long code instead of shrinking it. Put detailed demonstration steps, anticipated answers, misconceptions, timing, differentiation, and fallback instructions in notes. Include explicit pause/ask/test cues for demonstrations. Include substantive teaching content, not only slide titles.

Prefer progressive explanation using separate slides if animation is unavailable. Do not invent screenshots or interface states. Provide source attributions where needed. Render and inspect every slide for clipping, overlap, missing glyphs, code indentation, and projection readability.

## AI framework consistency

Carry selected framework-aligned objectives and task IDs through the plan, student worksheet, teacher answers, slides and notes. Keep the detailed crosswalk teacher-facing; express student criteria in plain language. Include individual explanations or transfer checks and evidence of evaluation, decisions and revisions, rather than treating a generated artifact as sufficient. Do not add all framework domains to a short lesson or confuse teacher competencies with student outcomes.

## Information and media literacy materials

Include source identity, publication date, context, claim or message, and enough evidence to perform the task. Use verified public examples or clearly labelled fictional teaching cases; never pass invented excerpts as real news. Provide an evidence table, space for evaluating source independence and uncertainty, and a reasoned sharing/presentation decision. Keep teacher verdicts and rationale separate from the student source pack. Assess reasoning against the evidence, allowing justified uncertainty or alternative interpretations. Avoid mandatory public posting or disclosure of student accounts.

## Complete-pack delivery

Default requested formats: editable DOCX for plan/worksheet/answers and PPTX for slides, unless the user specifies otherwise. Produce only requested resources. Verify student files do not contain answer material; verify notes and links are present. Report what was created and actual verification, with no unperformed test claims.
