# Curriculum maps and progression

## Map construction

Start with outcomes and the school calendar, not a catalogue of fashionable tools. Establish year levels, lesson length, weeks, interruptions, learner starting points, teacher expertise, devices, accessibility, and curriculum obligations. Use available teaching hours, with an explicit contingency allocation. Check totals.

Produce:
1. Context, assumptions, sources and dates.
2. End-of-stage outcomes and prerequisite diagnostic checks.
3. A map with columns: unit ID; year/stage; lessons/hours; prerequisite; concepts/outcomes; demo/project; inquiry and student decisions; assessment/readiness evidence; tools/fallback; support/extension; next connection.
4. A brief explanation of increasing conceptual depth and independence, including gaps and deliberate revisiting.
5. Implementation priorities, teacher preparation, and a concrete first unit.
6. An evaluation/review point informed by student evidence.
7. A lesson-by-lesson breakdown within each unit identifying the named platform, at least one bounded task to complete that lesson, minimum output, objective-linked success criteria, assessment evidence, and allocated time. A project milestone must be a completed assessable output, not simply "continue the project". Keep platform transitions purposeful and show any prerequisite setup.

Label intended, taught, and demonstrated outcomes separately if reviewing an existing curriculum. Never imply a draft map is officially endorsed.

## Suggested progression, not a universal mandated ladder

| Stage | Focus and examples | Readiness evidence |
|---|---|---|
| Foundations | Unplugged algorithms, sequences, patterns, decisions, digital citizenship | Explain precise instructions, predict results, fix a simple error |
| Visual programming | Scratch or Blockly-based environments; events, loops, conditions, variables; interactive stories or quizzes | Explain and independently adapt the logic |
| Representation bridge | Compare blocks, natural language, flowcharts, pseudocode, and short text programs | Trace and explain equivalent representations |
| Text programming | Python or JavaScript; types, functions, collections, input validation, debugging; data investigations | Write, explain, test, and modify manageable code |
| AI-assisted development | Requirements, small generated changes, review, testing, user feedback; bounded vibe coding projects | Explain the solution, reject flawed output, verify requirements |
| Agentic development | Decomposition, bounded delegation, plan review, change review, independent testing, rollback | Review a proposed plan and changes, verify results, justify intervention |

Adapt stages to readiness; do not assign them solely by age. Block-based languages are programming languages. Blockly is a toolkit for visual editors, not one universal school curriculum. Pseudocode is an algorithm representation, not an executable language or a compulsory gateway. Interleave representations where helpful. Introduce AI literacy and responsible use at suitable levels throughout; do not postpone all AI until after text programming.

Revisit sequence, selection, iteration, data, abstraction, testing, and human impact with increasing depth. Include digital literacy, systems, networks, data, security, accessibility, and ethical use where relevant; technology education is broader than coding.

## Information and media literacy as a parallel strand

Read information-and-media-literacy.md when mapping literacy. Include embedded objectives/activities within subject units and/or dedicated lessons according to context; do not force every literacy topic into coding or AI. Map selected Hong Kong literacy areas and key-stage targets, identify each subject/teacher responsibility where a whole-school map is requested, revisit targets with increasing independence, and avoid duplicating lessons across subjects. Assign a completed assessed task and evidence to each lesson, including standalone discussions or paper-based investigations. Preserve the time budget and existing subject learning.

## Jurisdiction profiles and source discipline

Ask for the actual jurisdiction and document/version when alignment matters. Use local obligations as the anchor; use other systems for clearly labelled comparisons. Do not mechanically equate Hong Kong forms, Singapore levels, US grades, or UK key stages.

- **Hong Kong:** read hong-kong-curriculum-elements.md for secondary learning-goal connections and requested values/national security integration; show selected elements, related units, activities and evidence in a compact companion map. Reference EDB curriculum guides and relevant primary/secondary supplements. For information/media literacy, use the supplied “Information Literacy for Hong Kong Students” Learning Framework (2024), especially categories/areas (pp. 3–7), key-stage targets (pp. 8–13), and whole-school implementation (pp. 14–17); see information-and-media-literacy.md for the verified synopsis. The teacher-supplied 2017 Technology Education KLA guide provides a broad framework. The supplied 2020 primary coding supplement addresses upper-primary computational thinking, programming constructs, variables, remixing, testing/debugging, and physical computing. The supplied primary Information and Innovation Technology AI extract identifies itself as a trial document: preserve that status and distinguish it from a final full framework. It describes early teacher-guided experiences and later development, verification, human judgement, and avoiding overdependence. Read the actual supplied documents for precise mappings; these notes are not substitutes for page-level verification.
- **Singapore:** consult MOE subject syllabuses and IMDA/MOE programmes separately. Code for Fun is an enrichment reference, not evidence that every school follows one identical compulsory sequence. Official starting point: https://www.imda.gov.sg/how-we-can-help/code-for-fun
- **United States:** identify state/district requirements where needed; do not describe CSTA as a compulsory national curriculum. Official starting point: https://csteachers.org/pk12standards/ . Check the edition and status at use time, including AI provisions.
- **United Kingdom:** identify England, Scotland, Wales, or Northern Ireland. England's computing programme is not a UK-wide curriculum. Official England starting point: https://www.gov.uk/government/publications/national-curriculum-in-england-computing-programmes-of-study/national-curriculum-in-england-computing-programmes-of-study

For each mapping record document title, issuer, jurisdiction, publication/version, status, relevant section/page or standard identifier, and the connection to the learning outcome. Cite public sources or teacher-supplied documents appropriately. Never invent standard identifiers, exact quotations, page numbers, or equivalences. Link to public documents rather than redistributing attachments without permission.

## Mandatory framework mapping for AI learning

Read ai-framework-alignment.md for AI units and lessons. Map each AI lesson to selected OECD/EU and UNESCO student competencies and levels, showing where objectives are introduced, practised, evidenced and revisited. Review balanced coverage across the full sequence; do not require all domains in every lesson. Keep OECD/EU Basic/Intermediate/Advanced distinct from UNESCO Understand/Apply/Create, and avoid equating school years with levels. Label an original task or crosswalk as teacher-designed. Use the verified 2026 OECD/EU publication rather than silently mixing it with the 2025 review draft.

## Emerging technology review

When requested, research and date-stamp a small selection of emerging approaches using official documentation, education bodies, or primary research. Consider AI literacy, AI-assisted coding, agentic workflows, physical computing, or data applications only where they serve the outcomes. Do not label these examples as the latest without checking.

For each candidate report: learning purpose; supporting source/date; prerequisites; age/account/access requirements; cost/device needs; privacy/accessibility implications; teacher preparation; pilot activity; evidence to collect; decision to adopt, adapt, defer, or omit. Separate product capability claims from educational effectiveness claims.

Define vibe coding as an AI-assisted approach and state the intended level of code review; require learning checks even when a prototype works. Define an agentic activity as bounded planning/execution/review with student oversight. Use sandboxes, synthetic data, reversible changes, and explicit approval boundaries for external actions. Do not connect student agents to real accounts, publishing, purchases, or unrestricted services by default.
